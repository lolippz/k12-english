Product Requirements & Feasibility

K12 英语在线学习平台 · 立项方案

版本 v0.1（讨论稿） 日期 2026-10-13 范围 小学 / 初中 / 高中

结论先行

这个方向技术上完全可行，且开源生态足以让你省掉 60% 以上的基础工作量。真正的门槛不在技术，而在三件事：内容版权、教育 App 备案合规、以及冷启动的获客渠道。

  1. 不要从 LMS 起手。Moodle / Open edX / Canvas 的代码里，教务、商城、课程管理占了 80%，与 K12 英语的核心学习闭环无关。只借鉴其数据模型。
  2. 直接复用四件套：ECDICT（词典数据）+ qwerty-learner（背单词交互与词库）+ ts-fsrs（记忆调度算法）+ LanguageTool（语法批改）。这四块加起来能省 4-6 个月。
  3. 差异化不在"更好的背单词 App"，而在校内进度对齐 + 老师布置作业闭环 + 学情数据打通。纯 C 端工具型产品打不过百词斩、多邻国。
  4. 合规前置。教育移动应用备案需 2-3 个月，且要求 ICP + 等保测评先行；定位必须避开"学科类培训"。

一、可参考的开源项目清单

按能力域拆成六类。每一类标注了 License 和复用建议——这是选型时最容易踩坑的地方：GPL 系传染性强，商用前必须逐条核对。

1. 背单词 / 间隔重复（核心入口，建议直接复用）

直接复用

qwerty-learner

最贴合你需求的项目。React + TypeScript，内置中考、高考、四级、六级、雅思、托福、GRE词库，含词典释义、音标、发音、听写模式、错题本。

  • 仓库：RealKai42/qwerty-learner
  • License：GPL-3.0（注意传染性）
  • 价值：交互范式 + 词库数据结构可直接借用
直接复用

FSRS / ts-fsrs

现代间隔重复调度算法，效果显著优于 Anki 传统的 SM-2。有 TypeScript 与 Python 双实现，可独立嵌入你的后端或前端。

  • 仓库：open-spaced-repetition/ts-fsrs
  • License：MIT（商用无风险）
  • 价值：记忆调度引擎零成本落地

直接复用

LanguageTool

开源语法与拼写检查引擎，支持 30+ 语言，英文规则最全，可自托管。作为写作批改的规则层，与 LLM 点评互补。

  • License：LGPL-2.1（可商用，需注意动态链接）
参考改造

GECToR / AutoGradAI

GECToR 是 Grammarly 开源的语法纠错模型（HuggingFace 有现成权重）；AutoGradAI 是基于 LangChain 的作文批改系统，其批改报告结构值得直接抄。

直接复用

分级阅读语料

StoryWeaver（Pratham Books，数千本多语种分级绘本，CC-BY）、Bloom Library（SIL 开源图书平台）、Project Gutenberg（公版书）、Simple English Wikipedia（A1-B1 难度）。

直接复用

可读性计算库，用 Flesch-Kincaid 等公式给任意文本自动估算难度分级，是做自适应推荐的轻量方案。

二、产品定位：三个必须先回答的问题

问题 1：你的付费用户到底是谁？

K12 的特殊性在于使用者与付费者分离。学生是使用者，家长是付费者，老师是渠道。

  • 纯 C 端学生自学：获客成本高，学生留存靠趣味性，但付费意愿弱（学生没钱）。
  • 家长付费：付费意愿最强，但决策链长，需要"可见的效果证明"——成绩、报告、老师背书。
  • 学校 / 老师：付费能力强、批量获客，但销售周期长，且需教育 App 备案与内容审核。

建议采用双边模型：学生端免费（获客）+ 老师端布置作业（留存与增长引擎）+ 家长端付费订阅（变现）。这是一起作业验证过的路径。

问题 2：差异化在哪？

百词斩、扇贝、多邻国、一起作业都已成熟。你不应该做"更好的背单词 App"。机会点有三个：

  1. 教材同步：按人教版/外研社/译林版单元词表与课文进度组织内容，刚需、高频、可标准化。这是纯工具型产品做不到的（它们只能做通用词表）。
  2. 校内闭环：老师布置作业 → 学生完成 → 自动批改 → 班级学情报表 → 家长推送。这条链路把"工具"变成"教学环节"。
  3. 学情数据打通：课堂表现、作业、考试、错题、复习记录统一建模，做薄弱点诊断与自适应推荐。这恰好是你在医疗信息化领域积累的系统集成与数据治理能力最能发挥的地方。

问题 3：合规红线在哪？（硬门槛）

  1. 教育移动互联网应用备案——教育部强制，前置条件是 ICP 备案 + 等级保护测评，周期通常 2-3 个月，必须最早启动。
  2. 双减政策——义务教育阶段学科类培训不得资本化运作、不得在线上开展营利性培训、不得超纲超前教学；高中阶段参照执行。定位必须是"学习工具 + 校内教学辅助"，而非"学科类培训机构"，这是产品定位的第一约束。
  3. 未成年人个人信息保护——14 岁以下需监护人同意与单独同意，不得过度收集，需提供家长查阅与删除通道。
  4. 内容版权——教材词表、课文、真题均受版权保护，商用需逐项授权；用户生成内容（作文、录音）需审核机制。

六、路线图

Phase 0 · 调研与预研2 周

确定教材版本范围（建议先做人教版小学 + 初中）；跑通 ECDICT 导入、qwerty-learner 本地运行、ts-fsrs 调度验证；启动教育 App 备案与 ICP 流程；确认版权授权的可行路径。

Phase 1 · MVP 上线内测8-10 周

完成单词、听力、基础练习、学情四个模块；招募 50-100 名学生内测；核心指标：次日留存 > 35%、7 日留存 > 20%、日均使用时长 > 12 分钟。

Phase 2 · 教学闭环与试点3 个月

上线老师端与作业闭环、写作批改、分级阅读、家长报告；签约 1-2 所学校做真实场景试点，验证老师的使用意愿与家长付费转化。

Phase 3 · AI 能力与自适应6 个月

口语陪练、自适应难度引擎、组卷与模拟考、教研内容生产工具。目标是形成"内容 + 数据 + 算法"的三重壁垒。

七、风险清单

内容版权（最高风险）教材词表与课文受版权保护，商用需授权。缓解：v1 用公版与 CC 授权语料 + 通用考试词表，同时并行推进出版社授权谈判。版权谈不下来，产品定位需退回到"通用英语学习工具"。
合规备案周期教育 App 备案需 ICP + 等保前置，周期 2-3 个月，且可能因内容审核不通过。缓解：Phase 0 就启动，不等到产品做完。
内容生产是最大瓶颈K12 英语的内容量级极大（每册每单元的词汇、听力、练习、解析），纯人工教研无法支撑。缓解：用 LLM + TTS + 模板化流程批量生成，教研只做审核与抽检。
获客成本高K12 家长决策链长，纯线上投放 ROI 差。缓解：走学校 / 老师渠道做 B 端切入，用老师布置作业带动学生与家长注册，形成自然增长。
巨头竞争百词斩、多邻国、一起作业在各自赛道已成熟。缓解：不做通用工具，做"校内同步 + 数据打通"的垂直整合，这是巨头不愿做的重活。
开源许可风险qwerty-learner 是 GPL-3.0、Canvas 是 AGPL-3.0，直接用于闭源 SaaS 有法律风险。缓解：GPL 项目只参考交互与数据结构，不复制代码；优先选 MIT / Apache-2.0 的组件。
